## 1. 五条硬约束的落实

1. **认领必须服务端原子**：`home_claim` 走 `/act`，在 `claimWildPlot`（`life/households.mjs`）里一次性完成
   “未认领 / 非荒野 / 距离 / 材料 / 可站 / 可建 / 可走”校验，之后**同一同步段**写
   `wildExpansion.claims + peripheralHomes + households.projects + locs + 扣材料`，写入后没有失败分支。
   重复认领/两人同抢返回 `PLOT_TAKEN`，且失败方不扣材料、不写状态（`V12-EXP-03`）。
   客户端只发意图：`#buildDlg` 与地块交互只发 `{kind:'home_claim', type:plotId}`，不本地先占。
2. **道路/碰撞同源**：接入路线在生成时由唯一的 `worldRoute`（`shared/asset-collision.mjs`）算好并存进地块记录；
   认领后 `campSceneContent` 用它画路。房屋 AABB 由 `wildHouseSolids()` 一处生成，
   client `buildWorld` 与 server `sceneSpace` 都把它传给同一份 `campSurface.extraSolids`。
   浏览器证据里客户端 `heightAtCenter=0`、`centerWalkable=false`、`colliders=['wild-house']`，与服务端
   `houseCenterWalkable=false` 一致；门前 `doorWalkable=true` 在完工前后都成立。
3. **室内移动只写 `w.pos`**：`life/room-walk.mjs` 只用 `placeActor` 写位置；不写 loc/occupancy/动作/需求。
   每步 `roomSurface.walkable(x,z,0.33)`；多人用“不进入重叠 + 已重叠只允许拉开”的严格避让；
   p1 完全跳过；进房落点由 `body.settleTravel` 换成门内点，出房仍走原有 portal 到同一扇门的世界点。
   `survView.agents[*].pos` 本来就在载荷里（P2c 已有），没有新增内部对象暴露。
4. **未认领地块零几何**：未认领时不进 `flatLand/clearing/reserved/roads`，也不生成入口/房屋；
   `wildPlots.plots[].road` 只在 `claimed` 后下发。金样画布 45/45 不变（这是硬证据，不是“应该看得见”）。
   认领/读档后由 `wildClaimSignature` 让 client `buildWorld` 与服务端 `sceneGeometry/sceneSpace` 缓存失效并重建。
5. **性能**：地块生成一次（seed 13 实测约 8–13ms，最多 8 个）；路线生成时一次；室内兴趣点按
   `world × room × 布局签名`缓存（`roomPois`），每分钟每人只做一次几何查询；没有每帧扫描。
   8 个地块上限写死在 `WILD_PLOT_MAX`。

## 2. A：荒野扩建的实现与接线点

### 2.1 生成（`shared/wild-plots.mjs`）

- 纯数据 + 纯几何，只吃 `mapSeed/layoutVersion`，无 RNG、Node/浏览器同构。
- 在 120×80 聚落矩形外环（外扩 6–20 单位）用种子哈希绕环取候选，硬筛：
  不在营地内、`bankGap≥2.2`（不压河/岸）、pad 与 lot 四角/中心/门逐点 `terrain.walkable`（不压树、可站）、
  四角高差 ≤1.1（坡度可建）、不压地标/落石、与已选地块间隔 ≥9。
- 每个地块再用 `worldRoute` 求“地块门 → 同岸最近村口站点”的可走路线（逐点 `walkable`，只保留聚落外沿），
  没有路线的候选直接丢掉（通路筛选）。最终 4–8 个，最多 8。
- layout 2 用 `generateCampLayout` 的站点/`crossZ`；**layout 0（内置种子档的实际形态）**用共享 `CAMP_SITES`
  与默认 `crossing=34`，与 content 的村口/桥保持同源。

### 2.2 状态与接入 housing

- `world.survival.wildExpansion = {enabled, plots, claims}`；`peripheralHomes` 是“已认领”的**唯一权威**。
- `initWildExpansion`（开局）与 `restoreWildExpansion`（读档）把 claims 合并回 peripheralHomes；
  `loadSurv` 在 `restoreHouseholds` **之前**先做一次合并，避免住宅→房屋映射丢失（这是读档顺序上的关键点）。
- 居民候选顺序：固定 9 块 → 外围 4 块 → 荒野候选（`stepHouseholds`）。荒野候选开工时才认领
  （`registerWildClaim`），此后 `homeLot/campEntrance/outdoorHomes/roomProps/homeRoads/homeEntry/household`
  全部复用既有链路；`residentialSite` 签名没有改。
- 玩家：`home_claim`（木 5 石 3，需 `playerPos` 距地块门 ≤1.45）与 `house_work`
  （连续动作 15 游戏分/次，+1 进度，3 次完工；完工走既有 `finishHome`）。
  `house_work` 只在玩家侧声明为长动作，居民日节拍不变（避免改居民轨迹/基线）。

### 2.3 客户端

- `survView` 只对正式游戏下发 `wildPlots`（候选 + 认领态；路只给已认领）。
- `#buildDlg` 增加“荒野宅基地”区：远处/缺料禁用，认领后可“继续施工”。
- 世界内地块门有可点击的射线面；手持锤子时出现“荒野宅基地”交互（hover 才出标签，首帧画布不变）。
- 已认领的在建房屋走既有 `workProjects` 入口（`houseWork`），完工后走 `outdoorHomes` 的门。

### 2.4 关键发现：生产主档是 layout 0

内置种子档 `seed/world.json` 的 `survival.layoutVersion = 0`（没有 `campLayout`），
原来 `constructionAccessEnabled` 只在 `layout≥2` 为真。若只按 layout 2 实现，正式游戏里根本不会出现荒野地块。
因此本轮：
- 生成与认领支持 layout 0/2（`V12-EXP-08` 用 layout 0 覆盖“生产主档同形”的完整认领→施工→存档链路）；
- layout 0 下施工可达性系统本来就是关闭的，所以荒野地块用**独立的共享空间预检** `wildPreflight`：
  lot 四角+中心可站、地块门可站、从地块门到 hall 有沿 `sceneSpace` 的路线；
- 既有固定地块的行为不变（`constructionAccessEnabled` 条件没有放宽）。

## 3. B：居民室内自由移动

### 3.1 实现（`life/room-walk.mjs`）

- 兴趣点：门 + 床/桌/火炉/长凳/工作台/水井/架/板条箱等（`roomPropsPx`），每个家具取“外圈可站”的点；
  不可站的点直接丢弃，因此兴趣点天然避家具/墙。
- 每分钟每个室内居民：目标选择（确定性哈希 + 每轮前进一格，避免只在家具 A/B 间往返；跳过已被别人占的目标）
  → 直线/单轴步进（步长 ≤ `WALK_UNITS_PER_GAME_MINUTE`=0.375）→ 每步 `roomSurface.walkable(...,0.33)`；
  被堵 2 次换目标；到达后停 0–1 游戏分钟再换。
- 多人：严格分离（不进入 2×0.33 重叠；已重叠时只允许把距离拉开的步子）；目标点被占则换下一个。
- 只写 `w.pos`（`placeActor`），不碰 loc/occupancy/动作/需求/决策；p1 跳过。

### 3.2 接线点

- `survplay.mjs` 的分钟循环：`stepBodyMinute` 之后、`worldTick`/think 之前调用 `stepRoomWalk(w, minute)`；
  只在 `actTimeModel` 的连续世界调用（研究态没有 pos，天然空操作）。
- 进房连续性：`body.settleTravel` 对居民改用 `roomEntryPosition`（门内可站点，避让同房间的人），
  随后由室内走动带去兴趣点；出房仍由既有 portal 把位置切到 `roomDoorPoint` 的门外点。
- 客户端：`roomCrowd` 优先读 `servView.agents[who].pos`（`room:<site>` 且 `roomSpaceFor(site).walkable` 复核），
  回退旧槽位；用两次快照的位移给 `moving/direction`（表现层）。玩家室内逻辑不变。

### 5.1 顺手修掉的两处（与本项直接相关）

1. **客户端视图缺口**：`wildClaimSignature/wildHouseSolids` 最初只读 `w.survival`，而客户端视图没有
   `survival`（只有 `wildPlots`）。浏览器证据先暴露了这一点（认领后客户端 `heightAtCenter=2.41`、无碰撞），
   改成同时接受 world/视图后，客户端才真正重建地基/道路/碰撞（`heightAtCenter=0`）。这是“双端同源”约束
   的实测结果，见 §2.2 与 `browser.log` 的前后两条记录。
2. **P1c-05 的 6µs 容差**：`nowMinutes` 是“真实时间→游戏分钟”的派生读法，读档返回到断言之间流逝的真实毫秒
   会按 1:10 计入；原断言 `<1e-6` 游戏分（=6µs 真实时间）在 211 个测试文件并行时是负载抖动（单跑 5/5 绿，
   全量偶发红）。本轮把容差改成 0.05 游戏分（=300ms 真实时间），仍能抓住“重锚到 0/610”这类错误
   （差几百游戏分）。这是测试稳定性修复，不涉及产品语义。
