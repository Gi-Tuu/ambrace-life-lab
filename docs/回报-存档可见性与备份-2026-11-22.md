## 1. 做了什么

### T1：A′ 访客只读投影（commit `8ed2f9f`）

- `life/host-world.mjs`：新增 `guestCampView(key)`，**独立白名单构造**，不复用 `survView` 再删字段。只返回：
  `guest`、`camp {key,name}`、`day`、`population`、`settlement`、`events`（最近 3 条，仅 `{kind}`，不带 agent id）。
  `day` 用与 owner 视图同一个 `dayOf(w.t)`；`settlement` 用与 `survView` 同一段终局判定；都没有第二套读数。
- `serve.mjs`：`/world` 的 owner 门在 owner 不成立时不再 403，改为返回访客投影；**只有 key 是 32hex 且已登记**时才投影。
  非法/未登记 key 仍走原 403（SAV-05 / N1 口径）。`/act`、`/saves/open`、`/ctl` 的 owner 门一行未动。
- `life/host.mjs`：facade 暴露 `guestCampView`；T2 另加了只读 `dataDir` getter。
- `web/app.js`：新增访客态渲染。识别 `j.guest` 后只显示摘要和文案
  「你在看别人的村子，不能操作；要用这台浏览器玩，请换个名字新开一段」，
  并隐藏会 403 的入口：继续生存、新开一局、进入对照、工具栏、背包；owner 路径不经过这个分支。
- 新闸门 `life/camp-guest-view.test.mjs`（SA15）覆盖：无 cookie 200 + 逐字段禁列、owner 完整 `survival` 回归、
  day/人口/settlement/最近 3 条事件与 owner 同刻一致、无 cookie 的 `/act` 与 `/saves/open` 仍 403、
  非法/未登记 key 仍 403、客户端文案与入口隐藏。

### T2：#52 营地备份（commit `c3fc040`）

- `serve.mjs`：
  - `SAVE_EXPORT_TOKEN` 未配置时 `GET /export`、`POST /import` **一律 404**（默认关闭，和 `/chat`、大脑中继同一纪律）。
  - token **只从 query** 读（`export_token`），`constantTimeEqual` 比较；错误 token 401；不按 IP 限流，
    导出/导入共用一只 token 桶（`EXPORT_BURST`/`EXPORT_REFILL_MS`）。
  - 响应/错误体不含 token，也不含 saves 绝对路径；不写访问日志行。
  - `/import` 单独放宽请求体上限（默认 32 MB），其余路由仍 64 KB。
- `life/camp-instances.mjs`：
  - `buildCampExport`：`index` + 每档 `<key>.json.gz`（base64）+ `<key>.owner.json` 侧车。
  - `importCampExport`：逐档 `imported/skipped/rejected`。顺序是
    **key 32hex 闸 → 解压 → `validCampArchive` → `campFile`/`realpath` 第二道闸 → owner 检查 → `writeArchiveAtomic`**。
    越界 key 在拼路径之前就 rejected；坏档绝不写盘；已有 owner 的档 skipped，不覆盖不换绑。
    导入后先尝试 `rebuildIndexFromSaves` 自愈，再 `writeIndex(..., {merge:true})` 重建/校验索引。
- 新闸门 `life/camp-export-import.test.mjs`（EXPORT-01..05）覆盖：未配 token 404、错 token 401、
  导出档数 == `/saves` 档数且逐档过 `validCampArchive`、换 `DATA_DIR` 导入后名字/day/store/owner 侧车恢复、
  坏档 rejected 且原字节不变、`../../etc` 等越界 key 零写入（整棵测试目录文件枚举不变）。

## 3. 改量披露（动了既有判据的期望值）

本单不得不改 3 处既有判据，全部是「无 owner / 他人 owner 读 `/world` 由 403 改 200 访客投影」的同一条口径变更；
**写路由与非法 key 的 403 一条没放松**。`SA5b`、`SA10`、`SAV-05` 的期望值一字未改。

1. `life/camp-routing.test.mjs` SA11：已登记营地无 cookie 的 `/world` 由 `403` 改为 `200`，并断言 `guest===true`、无 `survival`；
   穿越串 `../etc/passwd` 仍 403、未登记 32hex 仍 403、owner 视图仍 200。
2. `life/camp-routing.test.mjs` SA12：匿名读已登记营地由 `403 CAMP_NOT_OWNER` 改为 `200` + `guest===true`；
   带 owner cookie 的 200 与完整 `survival` 断言保留。
3. `life/audit5-security.test.mjs` SEC5-02：标题与三条正文同步为「无 cookie / 他人 cookie = 访客投影，owner = 完整 world」；
   `/saves/open` 的同名 403 `CAMP_OWNED`、`/act` 的 403 等写路由判据未动。

另外：SA14 的客户端静态判据未改，`CAMP_NOT_OWNER` 兜底仍保留（非法 key 的 403 仍会走到它）。

## 4. 没验到的（明说）

- **没有真浏览器 E2E 验证访客态 UI**：只做了服务端真 HTTP 闸门 + `app.js` 源码断言。按钮隐藏/文案在真实
  iframe（`*.ms.show` + `modelscope.cn`）里的表现没截图、没点验。
- **线上 token 未配置**：本机测试用进程内随机 token；没有、也不应该把生产 `SAVE_EXPORT_TOKEN` 写进仓库。
  线上 `/export`、`/import` 目前应仍为 404，直到 ops 加密文变量。
- **没有在真实线上镜像/真实 135 KB 存档上跑导出→部署→导入**：这是 T2 的真正目标场景，只能在提交日由持有 token 的人执行。
- 未单独验证：token 桶 429 路径、超大请求体 413 路径、并发导入、已有「无主旧档」被合法导入覆盖的那一种分支
  （现有判据只覆盖新档与已有 owner 档）。
- 未验证本次改动与线上旧镜像的兼容性（旧镜像没有这两个路由，回滚即整体 404，按设计无害）。

## 5. 下一步建议

1. 请 owner/ops 在「部署设置 → 密文变量」新增 `SAVE_EXPORT_TOKEN`，值不进仓库/docs/回报；未加之前两路由保持 404。
2. 提交日部署流程：**部署前** `GET /export?export_token=…` 落一份包 → 部署 → `POST /import?export_token=…`；
   导入前确认目标 `DATA_DIR` 的 `saves/` 与包内 key 不冲突，导入后看逐条 `imported/skipped/rejected`。
3. 复审合并前建议在本地真浏览器点一次「清 cookie 后打开 `/?mode=survival&camp=<key>`」：
   应看到访客文案与摘要，且看不到继续生存/工具栏/背包；再点主菜单改名新开，owner 行为应与改动前逐字一致。
4. 若接受「访客投影」这条口径，建议后续把 5 字段白名单写进 SA6 旁边的契约注释，避免以后有人“顺手再加一张场景摘要”。
