### 口径说明（SEC5-01 的“令牌姿态”）

审计建议与既有 `SEC3-02` 契约都是“配了 `CTL_TOKEN` 就只认令牌”。因此本批实现为：
- **未设令牌**：破坏性 `/ctl` 必须有服务端签发且与会话绑定的 nonce；自选 nonce、伪造头、无会话一律 403。
- **设了令牌**：破坏性 `/ctl` 必须有 Bearer/`x-ctl-token`；合法 nonce 也不能替代令牌（实测 403），
  **Bearer 本身即凭据，不再额外要求浏览器 nonce**（否则 CLI/运维无法在不先取 cookie 的情况下重置）。
  “无服务端 nonce 一律 403”针对的是 nonce/浏览器路径与所有伪造头路径：它们在令牌姿态下同样是 403。
  这与审计报告 `SEC5-01` 的修复建议（`ctlDenied` 在 token 存在时提前返回）一致；若要改成“令牌 + nonce 双因子”，
  需同步改 CLI 与 `serve-guard` 的既有契约，属独立决策。

## 5. 未修 / 风险

1. **SEC5-05 令牌姿态 MAIN reset**：前端仍只发 nonce，不发 Bearer，配置 `CTL_TOKEN` 时“新开一局”依旧 403。
   要彻底闭环需给 MAIN 建立一次性 owner 会话或前端支持 Bearer；本批未做。
2. **SEC5-04 会话配额不是身份**：脚本可反复 GET `/` 换会话；只能把“50 次匿名占满”抬高为“需要多轮换会话”，
   不能根治。真正根治需要账号/capability。
3. **DATA5-01 首个窗口**：flush/SIGTERM 已补写，但硬杀进程仍可能丢 ≤1 个 `SAVE_EVERY`（≤10 刻）；
   接受该语义或引入 WAL 属后续设计。
4. **DATA5-05 ownerHash 只在索引**：索引丢失仍会丢归属；重建索引不恢复 owner。
5. **ARCH5-06 未完全单源**：`S.model.calls` 内部路径仍是手写自增，`attempts` 仍分散（设计已给两步方案）。
6. **camp_* 前置检查**：`campAction` 仍保留位置/工具/库存拒绝，未收敛（设计已给按动作族迁移方案）。
7. **CI 浏览器用例**：已改为 `REQUIRE_CHROME=1`，但本批只在本机 Chrome 上验证；GitHub Runner 的
   Chrome 存在性与无头行为需下一次 Actions 记录确认（若 Runner 缺 Chrome，构建会按设计红，不会静默 skip）。
