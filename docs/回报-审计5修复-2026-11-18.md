### 口径说明（SEC5-01 / SEC5-05 的“令牌姿态”）

- **全局 `reset` / `compare_reset` / `catchup` / `brain`**：配置 `CTL_TOKEN` 时只认 Bearer；合法 nonce 也不能替代（实测 403）。
  “无服务端 nonce 一律 403”针对的是 nonce/浏览器路径与所有伪造头路径：它们在令牌姿态下同样是 403。
  这与审计报告 `SEC5-01` 的修复建议（`ctlDenied` 在 token 存在时提前返回）一致。
- **唯一的例外是 MAIN 的 `survival_reset`**（第二轮用户明确要求浏览器“新开一局”可用）：
  令牌姿态下允许“服务端会话 nonce”授权，但 nonce 一次性、60s TTL、全局 3 次/分钟限速，并写审计事件
  `[audit] main_reset {at,sid 前缀,result}`。**风险：任何能 GET 首页并拿到 nonce 的脚本都能重开 MAIN**
  （速率受限、可审计）；全局 reset 与具名营地不受此例外影响。
- 未设令牌时：所有破坏性 `/ctl` 都走服务端会话 nonce（一次性 + TTL），自选 nonce/伪造头 403。

## 5. 未修 / 风险

1. **MAIN nonce reset 的授权边界（用户明确取舍）**：令牌姿态下，任何能 GET 首页拿到会话 nonce 的脚本都能
   重开 MAIN；已用一次性 nonce + 60s TTL + 3 次/分钟 + 审计事件限损，但这不是身份认证。全局 reset、
   具名营地仍只认 Bearer/owner。若需要更强，应改为“前端显式输入 token”或账号 capability。
2. **SEC5-04 会话配额不是身份**：脚本可反复 GET `/` 换会话；只能把“50 次匿名占满”抬高为
   “需要多轮换会话”。真正根治需要账号/capability。
3. **DATA5-01 不可恢复窗口**：启动基线 + `SAVE_EVERY` 可配（默认 10）+ flush/SIGTERM 收口后，
   硬杀进程仍可能丢 ≤`SAVE_EVERY` 刻（默认 ≤10）；不做 WAL 就没有零丢失保证。运维可调小 `SAVE_EVERY`
   换取更短窗口（代价是写盘频率）。
4. **DATA5-05 旧营地无侧车**：首次启动后老营地仍按“首次 claim”兼容；侧车只在该营地下一次保存/claim 时生成。
   索引与侧车同时丢失时，归属仍不可恢复（需要外部备份）。
5. **camp_* 收敛只完成静态族**：位置/容器/库存/设施族仍留在 `campAction`；分阶段迁移方案已给，未一次搬完。
6. **CI 浏览器用例**：已改为 `REQUIRE_CHROME=1`，实际 Actions run id/结论见 `evidence/audit5/audit5.json`；
   若 Runner 缺 Chrome，构建会红而不是静默 skip。
