## §1 P2-1 compare 单侧暂停回放缺场景 fallback

**问题**：`replay-history.mjs` 的 tick 查询在请求分钟没有候选帧时，会退回
`frames.findLast(f => f.t === t)`，再用 `scene[side].t === t` 接受场景。新帧的
`scene.t` 是派生刻，于是 62 分的场景可以被 tick 1（=60 分）拿走；单侧暂停时还会把
另一侧场景/相邻分钟场景混进同一画面。

**改法**：
- 候选帧只按请求派生刻 `t` 取；优先取 `minute === t×60` 的帧，其次取“某一侧
  `minutes[side] === t×60`”的同 tick 帧；**删除跨分钟 `frames.findLast` 兜底**。
- 场景逐侧只认 `sceneMinutes[side][t×60]`。只有旧档（帧无 `minute` 且无 `minutes`）
  才允许退回 `frame.scene`，因为旧档一刻就是 60 分。
- 某侧缺场景时该侧显式 `null`，并返回 `sceneSides[side] = { minute, scene }`
  说明该侧实际记录分钟；两侧都缺才返回 `scenes = null`。部分缺场景时 `scenes`
  保留对象（`A:null,B:scene`），前端 `draw()` 已按侧显示“这一刻没有场景记录”。
- 无帧时返回 `REPLAY_NO_FRAME` + `minute`，不猜相邻帧。

**闸门**：
- `life/replay-history.test.mjs` RP-06（A 冻结 60 分、B 到 120 分：A=null、B 正常）、
  RP-07（62 分场景不得冒充 tick 1；两侧都不在请求分钟即 `REPLAY_NO_FRAME`）。
- `life/v11-compare.test.mjs` V11-CMP-10：真实 host 暂停 A、推进 B 100 拍后
  `host.replay({t:B.t})`，断言 A 缺场景=null、B 正常、B 场景来自 B 自己的分钟。

**变红法**：把 `scenes` 的“任一侧有场景”改回“两侧都有”，CMP-10 立即红
（`TypeError: Cannot read properties of null (reading 'A')`）；把候选/场景允许跨分钟，
RP-07 立即红（`相邻分钟场景不得冒充请求分钟`）。
证据：`evidence/p2-fixes/red-replay-cmp10.log`、`red-replay-rp07.log`。

## §2 P2-2 HUD 自估 msPerGameMinute 抖动

**问题**：`web/app.js` 用相邻两次 `/world` 的 `gameMinutes/serverNow` 差分估速，再夹在
0.55–1.6× 标称值；实测同一轮 86.9–135.9ms（标称 125），HUD 出现第二套速度读数。

**改法**：
- 新增纯函数 `web/time-view.mjs::clockAnchorFromView(view, at)`：只读
  `clock.msPerGameMinute/rate/paused`，`serverNow` 完全不参与。
- fallback 125ms 只在视图/字段缺 `clock` 时使用；`clock` 存在但字段缺失也按 125 兜底。
- `rate=0` 保留为 0（冻结语义），`paused=true` 保留；`interpolateGameMinutes` 对
  `rate<=0`/`paused` 直接停在锚点，不会回退成 125ms 继续走。
- `app.js::setClockAnchor` 改为 `clockAnchorFromView(view, performance.now())`，
  删除 `hudLastClockSample` 与所有差分/平滑/夹取代码。

**闸门**：
- 纯函数数值闸门 `T7b`：相邻两次 `serverNow` 差任意大，锚点逐位相同；服务端
  `250ms` 就用 250；缺 clock/字段回退 125；暂停与 `rate=0` 在 60s elapsed 后仍停在 360。
- 源码闸门 T7 追加：`setClockAnchor` 内不得出现 `serverNow/deltaMinutes/deltaMs/observed`，
  `hudLastClockSample` 必须已删除。

**变红法**：把 `FALLBACK_MS_PER_GAME_MINUTE` 从 125 改成 136，T7b 红。
证据：`evidence/p2-fixes/red-hud-t7b.log`。

## §5 sim-clock `state().t` 与 rate=0

**问题**：
- `state().t = floor(gameMinutes/60)` 没有 `nowTick` 的 `+1e-6` 浮点吸收，可能和
  `/world` 的 `survival.t`/`world.t` 差 1；
- `rate===0` 时 `gameMinutesAt` 用公式乘 0，`startMinutes=720` 会被归零；且
  `advanceMinutes` 在 rate=0 下除以 rate，语义含糊。

**改法**：
- `state()` 只算一次 `minutes`，`t = floor((minutes + 1e-6) / 60)`，与 `nowTick()` 同源。
- `rate=0` 用显式 `frozenMinutes`：初始化取 `startMinutes`；`setGameMinutes` 直接钉住；
  `setRate(0)` 冻结当前分钟，`setRate(>0)` 从冻结分钟继续且不跳变；`advance/advanceMinutes`
  在 rate=0 下不推世界（与 pause 同语义）。不除零、不产生 NaN。
- `pause/resume`、`JSON.stringify(clock.state())` 均有单测。

**闸门**：`CLOCK-06`（rate=0 + startMinutes=720 + setGameMinutes + pause/resume + 换回 1×）、
`CLOCK-07`（setGameMinutes 边界、state().t === nowTick()、暂停不欠不补）、
`CLOCK-08`（state JSON 往返、字段齐全、有限数/整数）。

**变红法**：把 rate=0 分支改回 `return 0`，CLOCK-06 红。
证据：`evidence/p2-fixes/red-simclock-rate0.log`。
