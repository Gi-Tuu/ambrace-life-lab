## 0. 开工前先回的三问（结论已验证）

### 0.1 服务端能否直接拿到同一份 trees / rocks / reliefFaces？

**不能“直接拿”，但可以“同源生成”。** 改造前 `trees/rocks/hills` 只存在于 `web/app.js buildWorld()` 的返回值；服务端 `construction-access.mjs` 是 `outdoorStage({trees:[], …})`。它们本身是纯确定性函数（输入只有 survView 的 mapSeed/layoutVersion/layout/rooms/districts/peripheralHomes/households/homeRoads，加共享纯函数 `campTerrain/campBeds/penLayout/campPlants/createCampOutskirts/forestDensity/reliefAt/hash2`），没有 `Math.random`、没有 DOM/ASSETS。

做法：把这段生成**原样抽成** `shared/camp-scene-content.mjs`，客户端 `buildWorld` 与服务端 `construction-access` 调同一个函数、给同源参数。为证明“抽取逐位不变”，另做了两件事：

1. 用 `git show HEAD:web/app.js` 的原始块与共享实现逐项对比（host/v0、seed13/v2、强制 layout）：`trees/rocks/bridges/roads` 全部 `JSON.stringify` 相等（见 §3.6 归因）。
2. 用 `P2B_RESIDENT_LEGACY=1 SPACE_V1=0` 跑 golden：**45/45 与 main 基线一致**。说明场景内容抽取没有改变客户端任何输出，P2b 的行为差异只来自居民速度与服务端施工几何。

### 0.2 A* 选哪套？

**保留 `shared/asset-collision.mjs` 的 `pixelPath` 作为唯一核心。** 理由：

- 它能跑任意 `tw×th`，支持 `cellAllows` / `edgeAllows` —— 桥、门、房间像素、绕人都能表达；`joinedRoute`（村外/跨区）已经用它。
- `web/walk.mjs astar` 只能吃 tile 栅格，无法表达边规则，且平局规则与像素 A* 不同（线性扫 open vs 二叉堆）。
- 收口方式：`astar` 变成 `pixelPath` 的薄包装（把“转向点”展开成 4 邻接逐格），保留 `K1–K4` 契约；`pathFromWalker` 的两个分支现在都落到同一核心。

### 0.3 预计哪些测试/长程证据会变？

开工时列了：P2-02、peripheral-reach V4-03、playerReach 几何相关用例、quickstart、golden；研究五面与 long-run 默认不启用 actTimeModel 应不变。实际结果：

- **必改**：`life/p2-space.test.mjs` P2-02（12/刻断言）、新增 `life/p2b-space.test.mjs`。
- **长程变**：`life/settlement-events.test.mjs` 风暴闸门（受损建筑 5→4、地块水分 .29→0.30、借料配对从“第 2 条必 delivered”改为按 requestId 校验）；balance 闸门见 §4.2。
- **未变**：研究五面 md5、研究态 dumpSurv、golden（冻结世界不推进居民）。
- **口径变化**：`playerReach` 对正式游戏的非移动/移动动作新增几何校验；室内 `campPlayerRoom + 16×12` 是显式房间空间，不按室外判。

## 1. 这一刀改了什么

### 1.1 `shared/camp-scene-content.mjs`：场景内容唯一来源（新文件）

- 输入：`mapSeed / layoutVersion / layout / camp / timber / sites / districts / peripheralHomes / households / homeRoads / ecoSources`。
- 输出：`trees / rocks / hills / bridges / bridgeCells / landscape / blockers / roads / reserved / flatLand / beds / roadDist / plantClearance / harvestNodes / terrainHash / river / streamCenter / streamHalfWidth` + 少量避让 helper。
- 原样搬移：土路曲线、桥分组、树/岩循环、山丘浮雕候选过滤、田块/圈舍/保留地避让；顺序、阈值、取整不动。
- `campSitesOf` / `staticCampSites`：把客户端 `sitesOf` 的公式与“只画固定地点”的过滤一并共享；服务端传 `w.locs`。
- 客户端 `web/app.js` 的 `buildWorld` 改为调用它（不再在 app.js 里保留第二份树/岩/桥生成）。服务端 `life/construction-access.mjs` 新增 `sceneGeometry()` / `sceneSpace()`：
  - `sceneGeometry`：同一份 sites/content → `outdoorStage`；`hills` 的传参与客户端一致（有 landscape 时传 `[]`，避免服务端多出客户端没有的浮雕层）。
  - `sceneSpace`：无 `campLayout` 的旧世界（layout 0）也能拿到与客户端同源的只读 space；按世界缓存，避免每次 `playerReach` 重建。
  - `mapFor` 改为复用 `sceneGeometry`，服务端 stage 从 `trees:[]` 变为真实树/岩/桥。

### 1.2 速度：`space.speedBudget` 一个表，居民不再独立 12/刻

`life/space.mjs`：

```js
SPEED_BUDGET_UNITS_PER_GAME_MINUTE = { walk: 0.375, sprint: 0.375 * 1.75 }
speedBudget(kind) / unitsPerTick(kind) / travelTicks(distance, kind, min=2)
GAME_RESIDENT_UNITS_PER_TICK = unitsPerTick('walk')   // 22.5/刻
```

- 居民 `startMove`：正式游戏（`survival.actTimeModel === true`）用 `travelTicks(distance,'walk')`；研究态/旧档仍 12/刻。
- 玩家移动上报：`player_sync` 仍按 sprint 39.375/刻；非移动动作按 walk 22.5/刻（P2 口径保留）。
- 同一路径：居民与玩家“步行”都取 `speedBudget('walk')`；冲刺是同一张表里的显式倍率，不是第二套预算。
- 探针开关（只用于证据，正常游戏不设）：
  - `P2B_RESIDENT_LEGACY=1`：居民回 12/刻，用于 golden/长程归因。
  - `P2B_RESIDENT_SPEED=sprint`：居民也按冲刺，用于证明“为何选 walk”（见 §4.2）。

### 1.3 A* 收口

- `web/walk.mjs`：删除本地 open-list A*，`astar()` = `pixelPath()` + 转向点展开；`isWalkable`/`stepWalker` 不变。
- `web/collision.mjs`：`pathFromWalker` 的两个分支（tile 降采样 / 像素）现在都调用同一核心。
- 结果：客户端像素 A* 与 `shared/asset-collision` 不再各一套；`joinedRoute` 仍是村外窗口化包装，但核心也是 `pixelPath`。

### 1.4 `playerReach` 几何校验

`life/survplay-camp.mjs`：

- 正式游戏（`actTimeModel === true`）在距离校验通过后，要求目标点 `space.walkable(x,z, CAMP_BODY_RADIUS=0.33)`：
  - 室外：`constructionSpace(w) ?? sceneSpace(w)`；
  - 室内：`w.campPlayerRoom` 存在且 `roomContains(x,z)`（16×12 显式房间空间）→ 放行，不按室外 stage 判；
  - 非法几何 → `OUT_OF_REACH`；超速/瞬移仍是 `TELEPORT`；WILDS 外仍是 `OUT_OF_REACH`。
- 首次定位（服务端给的出生槽 ±2）**不做几何校验**：出生点是服务端槽位、客户端还没走过一步；否则随机地图上服务端自己给的出生点都可能被拒（实测 camp-compare 用例）。几何校验从“位置已确立后的移动”开始。
- 研究态/旧时间模型不变（无连续地形，保持原口径）。
- 与既有码义对齐：外围 `gather` 若一次上报把位置搬动 >20 且仍不在工点，返回 `TELEPORT`（对齐 `camp-compare-entry` 的 otherContact 伪造）；`plan` 与小修正仍返回 `OUT_OF_REACH`（对齐 `camp-districts` 的地块用例）。两类都是拒绝，区别只在错误码语义。

## 4. 长程 / 轨迹变化清单（不静默）

### 4.2 平衡闸门：为什么居民取 walk 而不是 sprint

- 居民 39.375/刻（`P2B_RESIDENT_SPEED=sprint`）实测：
  - B1 100 日平均人口 **9**（[10,9,9,8,9]，闸门 [4,8]）；
  - B2 200 日灭绝 **0/5**（闸门 [1,3]）。
  - 证据：`sprint-balance.log`。
- 居民 22.5/刻（最终实现）：B-01/B-02/B1/B2 全部原样通过，无需改平衡阈值。
- 结论：居民与玩家“同一 speedBudget 表”，居民按 **walk** 档出行；冲刺是玩家移动上报的显式能力（×1.75），不是第二套速度。这样既去掉了独立 12/刻，也没有把 100/200 日平衡推翻。

### 4.3 其它数值变化

- quickstart：公仓吃前 25（P2 为 21）；walkMoved 1.7（按键帧时序本来就有 1.5–2.05 浮动）。
- golden：无差异（冻结世界不推进居民）。
- 研究五面/long-run 默认不启用 `actTimeModel`：逐位不变。

3. **居民仍无连续路径**：`startMove` 是锚点旅行（直线或施工路线长度 → 刻数），不是逐格 A*；本刀统一的是“预算/入口”，不是把居民改成连续行走。
4. **playerReach 几何只对正式游戏（actTimeModel）生效**；研究态/旧时间模型保持原口径，避免旧档/研究面变化。
5. **首次定位不做几何校验**：出生点是服务端槽位；若客户端在非法出生点静止，后续同一位置的上报会被拒（服务端回传同一位置，不会把玩家拉走）。这是“服务端出生点未做几何筛选”的遗留，属后续位置统一阶段。
6. **A* 仍是两个包装**：`astar`（tile 契约）与 `joinedRoute`（村外窗口）都包 `pixelPath`；核心只有一个，但入口函数名仍有两个。
7. **fallback 开关**：`SPACE_V1=0`（施工谓词回旧）、`?space=legacy`（客户端回旧栅格）、`P2B_RESIDENT_LEGACY=1`/`P2B_RESIDENT_SPEED=sprint`（仅证据探针）。
