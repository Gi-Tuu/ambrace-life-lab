## 1. P0：天气/昼夜床接线（槽位名 ≠ 素材名）

### 1.1 根因（审计已定位，本次确认）

`web/audio.mjs` 的 `setBed(name, want, gain)` 第一参数是**槽位名**，但旧实现把它直接当素材名：

```js
// 旧
const buf = stereoBuffer(`amb:${name}`, () => renderAmbience(name));
```

`renderAmbience()` 只认 `rain/wind/cold/day/night/crisis`，其余返回 `null`（`web/audio-data.mjs:577`）；
`cache()` 对 `null` 直接返回 ⇒ `play()` 返回 `null` ⇒ `setBed` 静默 `return`。所以：

- `setBed('weather', 'rain', …)` 实际执行 `renderAmbience('weather')` ⇒ `null`；
- `setBed('daynight', 'day', …)` ⇒ `renderAmbience('daynight')` ⇒ `null`；
- 只有槽位名恰好等于素材名的 `wind`、`crisis` 能建层。

### 1.2 修复

1. **槽位/素材分成两个参数**：`setBed(slot, material, gain)`，缓存键改为 `amb:${material}`。
   - `weather` 槽可选 `rain/wind/cold`；`daynight` 槽可选 `day/night`；`wind`、`crisis` 各自单素材。
   - `BED_SLOTS` 在 `web/audio-events.mjs` 集中登记，`audio.mjs` 用它做边界校验，测试用它做清单对账。
2. **天气按 climate 选素材**（纯函数 `weatherBed(climate, weather)`）：

   | 气候/天气 | 素材 | 说明 |
   |---|---|---|
   | `storm` / `weather=rain` | `rain` | 风暴按雨声底 |
   | `coldsnap` / `frost` / `snow` / `weather=cold` | `cold` | 寒潮/雪/冷天 |
   | `drought` | `wind` | 干旱的干风（村内；出村后由 proximity 风床接管，不叠两份） |
   | 其他（clear） | `null` | 不硬塞一层"底噪" |

3. **昼夜槽**：`dayNightBed(phase)` = `夜 → night`，其余 `day`。
4. **换素材时换缓冲**：`rain → cold` 时旧层淡出、新层淡入；缓存键按素材走，不会复用 `amb:weather`。
5. **climate 从世界读数传入**：`web/app.js` 的 `syncAudioScene` 增加 `climate: campClimate(sv)`（复用
   `web/camp-weather.mjs` 的同一份 `storm/frost/snow/drought` 判定），不再在音频层另写一套天气规则。
6. **签名补 climate 依赖**：`sceneSignature` 加入 `disasterToday/drought`，否则天气床换素材时
   900ms 轮询不会重排。

## 2. P1：BGM 与天气音效的相对电平

### 2.1 修复前

- 没有 ducking/sidechain；`musicBus` 只由 `fadeMusic(musicTarget(...))` 写，天气床不参与。
- 天气/昼夜四条床从不发声（§1），所以“rain 比 BGM 高 3.9dB”是**修好接线后才会出现**的静态风险；
  审计的实测数字为：rain 旧增益 0.5 时若发声约 **-27.7 LUFS**，比 spring BGM **-31.6** 高 **3.9dB**；
  day 床 **-45.1**，比 BGM 低 **13.5dB**；night 床 **-34.6**，比夜曲 **-36.4** 高 **1.8dB**；
  crisis 床 **-27.5**，比常规 BGM 高 **4.1dB**。

### 2.2 修复：LUFS 归一 + 显式 ducking

- `AMBIENCE_LUFS`：2026-11-21 用 `ffmpeg ebur128` 实测的素材级 LUFS（rain -18.6、wind -24.0、
  cold -27.4、day -34.0、night -28.4、crisis -19.2）。
- `BED_GAIN = 10^((BED_TARGET_LUFS − 素材LUFS)/20) / 0.7`，目标有效 LUFS：
  rain -39.5、cold -39.5、day -39.5、night -40.0、wind -33.0、crisis -30.0。
- 天气床在场时，**只对常规日曲**（bus 0.6）做 **-2dB** ducking（`MUSIC_DUCK_WEATHER=0.7943`）；
  危机（0.45）、夜曲（0.42）、送别（0.5）、灭绝（0.35）本来就更低，不再压，避免恢复期的雨声反超 BGM。

### 2.3 修复后有效电平（压缩器之前；master=0.7）

| 声道 | 素材 LUFS / 峰值 | 旧增益 → 旧有效 | 新增益 → 新有效 |
|---|---|---|---|
| rain 床 | -18.6 / -9.3 dBFS | 0.500 → **-27.7** | 0.129 → **-39.5** |
| cold 床 | -27.4 / -13.1 | 0.500 → -36.5 | 0.355 → **-39.5** |
| day 床 | -34.0 / -14.8 | 0.400 → **-45.1** | 0.758 → **-39.5** |
| night 床 | -28.4 / -14.0 | 0.700 → **-34.6** | 0.376 → **-40.0** |
| wind 床（prox 0 参考） | -24.0 / -12.4 | 0.250 → -39.1 | 0.507 → **-33.0** |
| crisis 床 | -19.2 / -10.5 | 0.550 → **-27.5** | 0.412 → **-30.0** |
| BGM spring（昼） | -24.1 / -10.5 | bus 0.60 → -31.6 | 雨天 duck 后 **-33.6** |
| BGM spring-night | -25.8 / -8.9 | bus 0.42 → -36.4 | 不变 |
| BGM crisis | -25.2 / -8.9 | bus 0.45 → -35.2 | 不变 |
| BGM extinct / death | -24.8 / -8.8、-25.1 / -8.9 | 0.35 / 0.50 → -37.0 / -34.2 | 不变 |

| 村内 危机 vs rain | -35.2 | -39.5 | +4.3dB |
| 村外 vs wind（BGM 不播） | — | -33.0 | — |

### 2.4 SFX 峰值与总混音余量

- 实测最响单条 SFX `chop` 峰值 **0.5**（A-02 上限 0.62），按实际调用增益 0.8、master 0.7 ⇒ **0.2800**。
- 最响 BGM 峰值 `autumn` -8.8dBFS，按 bus 0.6、duck 0.7943、master 0.7 ⇒ **0.1271**。
- 最响床峰值 `day` ⇒ **0.0956**。
- 三者保守相加 **0.5026（-5.97dBFS）**，余量 **5.97dB**，不削顶。计算在总线压缩器之前；
  压缩器（-16dB、knee 24、ratio 3、4ms/0.22s）只在总和越阈值时整体轻压，不会把上述相对关系反转。

## 3. P1：BGM 触发边界

### 3.1 根因

旧判据是 `playerDistance(sv) > FAR_RADIUS(70)`；镇矩形是 `120×80`，半对角 **72.1**，镇角 `(119,79)`
距核心 **70.7** ⇒ 在镇内却 `away`。反过来距核心 70 的 `(130,40)` 在矩形外却会播。

### 3.2 修复

- `CAMP_REGION = { west:0, north:0, east:TOWN_SIZE.width, south:TOWN_SIZE.depth }`，与
  `shared/camp-layout.mjs` 的 `TOWN_SIZE` 同源，不再各写一份半径/尺寸。
- `inCampRegion(pos)` / `playerInCamp(sv)`：优先 `sv.playerPos`，旧档退回 `locs[loc.p1]`，都没有时
  按“在村内”兜底（与旧 `playerDistance` 的兜底一致）。
- `computeWindow` 先判 **灭绝**（全图播）→ 再判 **玩家倒下**（`player-dead`，由 `audio.scene`
  播送别曲）→ 再判聚落矩形；顺序与旧实现一致，**“灭绝/倒下仍播”的语义不变**。
- `FAR_RADIUS=70` 保留，但只服务 `proximity()` 的风床/环境床连续衰减，不再决定 BGM。

### 3.3 边界矩阵（修复前 → 修复后）

| 位置 | 距核心 | 在矩形内 | 修复前 | 修复后 |
|---|---:|---|---|---|
| 镇中心 (60,40) | 0 | 是 | play spring/busy | play spring/busy（不变） |
| **镇角 (119,79)** | **70.7** | **是** | **play:false, away** | **play:true, busy-day, 0.60** |
| x=120 镇外 | 60.0 | 否 | play（半径内） | **away** |
| x=130 距核心 70 | 70.0 | 否 | play spring/busy | **away** |
| 村外 夜 | 70.0 | 否 | away | away |
| 村外 晨 | 70.0 | 否 | away | away |
| 村外 灭绝 | 70.0 | 否 | extinct | **extinct（不变）** |
| 村外 倒下 | 70.0 | 否 | player-dead | **player-dead（不变）** |
| 村内 夜 | 0 | 是 | spring-night 0.42 | 不变 |
| 村内 夜+危机 | 0 | 是 | crisis 0.45 | 不变 |
| 村内 夜+恢复 | 0 | 是 | recovering 0.60 | 不变 |
| 村内 恢复·昼·忙 | 0 | 是 | recovering 0.60 | 不变 |

### 3.4 菜单 / 村外 / 夜间 / 恢复的明确规则

- **菜单**：`audio.menu(true)` 用独立 `menu` 主题、电平 0.6，不读世界位置；`web/app.js` 的
  `if (ui.menu) { audioSceneSig = null; audioWindowSig = null; return; }` 保证世界场景不顶掉菜单曲。
- **村外**：聚落矩形外即 `away`，白昼/晨/暮/夜都不播；灭绝是唯一与位置无关的 BGM 例外。
  风床仍按 `proximity` 连续出现。
- **夜间**：村内播 `${季节}-night`，电平 0.42；危机/恢复主题覆盖夜曲并保留各自总线电平
  （crisis 0.45、recovering 0.6）——这是本轮明确的既存口径，本次未改，A-34 已钉住。
- **恢复**：村内照常按“晨/暮整段、白昼忙碌 6 播 6 歇”的规则播 `recovering`；没有距离豁免。
- **倒下**：窗口返回 `play:false, player-dead`，`audio.scene` 的 dead 分支直接起 `death` 曲并停天气/
  昼夜/风床、只留 crisis 心跳；这条语义未改。
