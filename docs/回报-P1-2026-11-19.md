## 1. 这一刀到底改了什么

### 1.1 新增连续时钟

`life/sim-clock.mjs`：

- `Clock { anchorMs, rate, pausedAtMs, msPerGameMinute }`
- `nowMinutes()`：唯一世界时间真相。
- `nowTick()`：`floor(nowMinutes / 60)`，保留旧"刻"量纲。
- `advance(ms)` / `advanceMinutes(m)`：测试、床、离线补时显式推进。
- `setGameMinutes(m)`：读档时重锚，不把装载耗时写进世界时间。
- `pause()` / `resume()`：暂停期间冻结，恢复时把 anchor 往后推同样时长，不欠不补。
- `setRate()`：换挡不跳变。
- `createTokenBucket({ capacity, refillMs })`：真实毫秒算力令牌桶。

默认 `msPerGameMinute = TICK_MS / 60`，`TICK_MS=7500` ⇒ **125ms / 游戏分钟**，与现有 7.5s / 60 分观感一致。`rate` 读 `GAME_SPEED`，默认 1。

### 1.2 正式游戏动作时间

`life/survplay-actions.mjs` / `life/resident-time.mjs`：

- 玩家正式游戏路径删掉"本刻 60 分池"和 `TIME_WAIT` 拒绝。
- 短动作（采集/移动/吃/休息/社交等）仍在同一次输入内原子完成；日统计继续记 `usedMin`。
- 长动作（`build/till/repair/expand`）创建 `busy { startMin, endMin, lastAdvanceMin, totalMin, remainMin }`，由 `endMin` 决定完成点，可跨刻、可在刻内任意分钟完成。
- 玩家 HUD 的 `timeLeft/timeMax` 在连续路径改为"今日剩余 / 1440"（前端原本在 `timeMax===1440` 时自动显示"今日时间"），不再用 60 分池。
- 旧路径（`gameRules:false`、`simTime:false`、`V72_TIME=0`）原样保留 60 分池、`TIME_WAIT`、chunk 推进。

### 1.3 输入解耦

`life/host.mjs` / `life/host-world.mjs`：

- `/world` 的 `readWorld` **不再进 `tickChain`**；直接同步快照后返回 Promise。tick 在模型/居民等待中时，读也能立即返回一致状态。
- 普通生存 `/act`（除 `talk_say`、`camp_sleep`）走新的短串行 `actChain`：只串行状态提交，不再等当前整拍；模型等待不会把它挡在后面。
- `talk_say`（会 await 模型）与 `camp_sleep`（内嵌多拍结算）仍走原 `queueWorldWrite`，避免在整拍中途做多拍重入。
- `pause/resume` 现在会同步暂停/恢复各生存世界的 `simClock`；否则暂停期间真实时间继续走，恢复会凭空跳一段。

### 1.4 居民最小 think 节拍

`life/survplay.mjs` / `life/agent.mjs`：

- 连续路径下居民决策机会按游戏分钟到期（`THINK_EVERY_MIN`，默认 10 游戏分钟）。
- 实际调用受真实毫秒令牌桶限流（`THINK_BUCKET` 默认容量 6，`THINK_REFILL_MS` 默认 1000ms）；手动 `step`/离线补时绕过桶，避免测试和快进被饿死。
- 每次 tick 每人最多 `THINK_MAX_PER_TICK`（默认 2）次；到期未消费的额度留到下一次 tick。
- **busy 不再提前 return**：身体干活时头脑仍感知/评价/决策；行动被 `execute` 以 `BUSY` trace 拒绝。旧路径仍保留"busy 占住决策机会"。
- `CHAIN_MAX` 同刻追加只在旧路径生效；连续路径由 think 节拍自然产生多次决策。

### 1.5 存档/读档

`life/survplay-save.mjs`：

- 只有 `simClock` 存在时才写 `clock` 字段；研究态 `dumpSurv` 不出现新字段。
- 读档时把时钟重锚到存档 `gameMinutes`（旧档没有该字段则按 `t*60` 接上），读档磁盘/反序列化耗时不会写进世界时间。
- 旧 `busy { startTick, remainMin, progressMin }` 在首次 `clockOf` 时自动补成 `startMin/endMin/lastAdvanceMin`。
- 连续路径跨午夜不再 `DAY_END` 砍掉进行中的动作；只重置日统计。

## 2. 旧路径隔离方式

只有一条开关：`createSurvPlay({ simTime: true, gameRules: true })` 才创建 `world.simClock` / `world.think`，并写 `world.simTime`。

- `createSurvPlay` 默认 `simTime: false`：现有 179 个测试文件里大量直接调 `createSurvPlay` 的旧语义用例**完全不受影响**。
- `host.survivalOptions()` 对正式游戏显式传 `simTime: process.env.SIM_TIME !== '0'`（默认开；`SIM_TIME=0` 可整体退回旧每刻池）。
- A/B 对照 / 研究面在 `host-replay.makeComparison` 里强制 `simTime: false`，保证研究轨迹逐位可复现。
- `gameRules:false` 时即使传 `simTime:true` 也被忽略（新测试 P1-05 钉死这一点）。

因此：

| 路径 | 时间模型 | 行为 |
|---|---|---|
| 正式游戏（host + GAME_RULES=1） | 连续时钟 | 去每刻池、长动作跨刻、输入解耦、think 节拍 |
| A/B 对照、研究态、`gameRules:false` | 旧 tick 计数器 | 逐位不变 |
| `SIM_TIME=0` / 显式 `simTime:false` | 旧 tick 计数器 | 兼容回退 |

## 5. 明确未完成 / 边界

1. **结算点仍在拍边界。** `tickSurvPlay` 仍一拍结算一次；连续时钟只让 `w.t` 变成派生量。自动 tick 默认 7.5s = 60 游戏分，所以长动作可跨拍按 endMin 完成；但没有 1 游戏秒 micro-step / Timeline 堆。`tickSurvPlay` 还有"直接调用时一次至少推进 60 分"的迁移期保底（手动 step/测试不卡住）。
2. **居民 think 是最小版。** 有"10 游戏分到期 + 真实毫秒令牌桶 + 每拍上限"，但没有完整 `ThinkScheduler`（无异步模型落地快照、无 continue/interrupt/switch 意图、无紧迫度排序）。busy 会思考，但行动仍被 BUSY 拒绝，没有"中断当前动作改做别的"。
3. **长动作开始时不预检材料/距离。** 规则层仍在完成时裁决；玩家可以在材料不足时先把活排进时间轴，30 分钟后再收到失败。短动作仍是原子成功/失败。
4. **离线/读档补时仍是旧路径。** 读档按存档分钟重锚，不把停机真实时间自动补进世界；`catchUpSurvival` 仍按"一刻=60 分"逐拍跑，没有合并到 `rate` 路径。
5. **前端只借了现成文案。** `timeMax=1440` 触发"今日时间"；busy 卡片仍写"本刻时间"标签，但数值是动作剩余。未改渲染/布局。
6. **输入短锁只覆盖普通生存 act。** `talk_say`（模型等待）、`camp_sleep`（多拍）、compare 仍走原 `tickChain`；没有做完整的命令队列/快照双缓冲。
7. **A/B 对照仍是旧时间。** 这是有意的研究面隔离，不是遗漏；连续时钟的长期行为读数需要后续单独重测。
8. `world.t` 仍有约 809 处引用，只降级为派生量，没有全仓替换。
