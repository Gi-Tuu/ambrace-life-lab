## C. `heightAt` 单一实现评估（只评估，未改）

### C.1 事实

- `life/space.mjs:173` `floorHeight(floors, x, z)`（9 行循环）；
- `shared/camp-scene.mjs:55` `stage().heightAt(x, z)`（同样的 9 行循环）；
- 两边已经 import **同一个** `floorContains`（`shared/camp-terrain.mjs`），语义逐字相同（仅空格差异）：

```js
let y = 0;
for (const f of floors) {
  if (!floorContains(f, x, z)) continue;
  if (f.triangle) { y = Math.max(y, f.y + f.ax * (x - f.x) + f.az * (z - f.z)); continue; }
  const t = f.axis === 'x' ? (x - f.x) / f.w : f.axis === 'z' ? (z - f.z) / f.d : 0;
  y = Math.max(y, f.y + (f.end - f.y) * t);
}
return y;
```

调用面：`campSurface().heightAt` 与 `createSpace().heightAt` 走 `floorHeight`；`stage.heightAt` 只被 `camp-scene.mjs` 的 `prop3d` 摆件用到（`:1037`）。

### C.2 “单一实现 + 薄适配”方案（建议单独一刀）

1. 在 `shared/camp-terrain.mjs` 导出 `floorHeight(floors, x, z)`（与现有 `floorContains` 同文件，天然被两端共享）；
2. `shared/camp-scene.mjs` 的 `stage().heightAt` 改为 `return floorHeight(floors, x, z);`；
3. `life/space.mjs` 删除本地 `floorHeight`，改 import；
4. 不新增依赖边（`camp-terrain` 已被两边 import）。

### C.3 风险评估：技术低、验收中

- **技术风险低**：纯函数、无状态、公式逐字相同、`floorContains` 已是同一份；`stage.heightAt` 与 `floorHeight` 的输入都是 `floors` 数组。
- **验收风险中**：`heightAt` 同时喂 22,000 点空间 parity、玩家脚高、摆件落地、房间地板（`roomHeightAt` 对房间显式 `ROOM_FLOOR_Y`，不经过 floorHeight）。必须重跑：
  - `node scripts/p2-space-parity.mjs`（要求 22,000 点 0 diff）；
  - `node scripts/redo-p0-golden.mjs --label <x>` + `p2-golden-compare`（45/45）；
  - `p2b-space`/`p2c-space` 与全量 `npm run check`；
  - 若 golden 中 `scene3d` 只哈希 boxes/floors 数量，仍应以 parity 为位移主证据。
- 本次**没有硬改**：任务要求先评估，且 A/B 两个 commit 都不应混入运行时代码。建议 A/B 合并后再单独提交 `C：floorHeight 单一实现`，验收同上。
