## 2. 复测与瓶颈分段（profile 证据）

### 2.1 首帧：时间去哪了

基线分段（`evidence/redo-p3/first-frame-segments.json` + 本轮临时 `?perfseg=1` 探针，探针已固化在代码里、默认关闭）：

| 段 | 基线 cold survival | 本轮中间态（seg3） | 最终态（seg8 → c4/p3） |
|---|---|---|---|
| navigation → 模块求值开始 | ~67 ms | 88 ms | 89–115 ms（含机器抖动） |
| 模块求值（含 WebGL 装配/编译） | 137.7 ms（createCampRenderer 132.5） | 9.1 ms + 首帧 `glSetup` 119.7 | 9 ms + `glSetup` ~109 |
| buildWorld | 254.7 ms | 292.5 ms | **225–237 ms**（profile p50 237.1） |
| buildWorld → 首帧（场景装配 + 首绘 + 上传） | ~343 ms | 130.6 ms 干跑 + 汇编 | **stage 网格 31.9 ms + region 延迟到下一帧** |
| 首帧总计 | 825.2 ms | 818.5 ms | **680.6–688.1 ms** |

关键归因（`evidence/debt-perf/seg*.json`、`buildworld-profile*.json`）：

1. **首帧 GL 网格上传/构网格** 曾是最大单块：`stage` 一个 buffer 2,641,230 floats（10.6 MB），旧 `quad()` 用 4 个数组展开 `push`，实测 **55.3 ms**；`regions` 16 个 buffer 再 ~28 ms。改为 15 参显式 `push` 后 stage 降到 **31.9 ms**（seg8）。
2. **buildWorld 的道路距离采样**：`terrainKinds` 在 2 px 网格上问 ~61 万次 `roadDist`，旧实现 `reduce + distSeg + Math.hypot` 每段一次；profile 里 `reduce` 回调 55 ms + `distSeg` 52 ms。内联 for 循环、逐段平方距离比较、最后对胜出段做一次 `Math.hypot`、道路桶 64→32 px 后，buildWorld p50 从 **281→237 ms**（同负载 profile），官方 harness 225–232 ms。
3. **着色器编译**：冷启动 `createCampRenderer` 132 ms 里主要是主 program 的编译/链接（旧代码还额外编译了一个**从未被使用**的 bloom/post program）。删掉死代码后，把 COMPILE/LINK 状态检查与 uniform/纹理装配延迟到首帧 `render()`（模块求值 132→4 ms），但状态查询本身仍要等驱动编译（~110 ms，SwiftShader 惰性编译）。这是冷启动目前最硬的剩余成本（见 §5）。
4. **室外帧率**：基线 4 s 采样 32.4 fps / p95 50 ms；CPU profile 显示每帧 JS 14.3 ms，其中 `rawHeight` 4 s 内 338 ms（居民/动物贴地、接触阴影重建、视野射线各问一次地形高度），`campSight` 视野网格、`coveredModels` 屋顶射线每帧重算。最终每帧 JS **8.1 ms**，fps **45.5**、p95 **33.4**（`evidence/debt-perf/fps-profile.json` / `fps-profile-c4.log`）。

## 3. 改了什么（按收益排序）

### A. 3D 首帧（`web/camp-3d-render.mjs` + `web/app.js`）

1. **首帧 DPR/质量策略**：新增 `render({ resolutionScale })`；第一张 3D 帧以 **0.5×** 内部尺寸渲染（SwiftShader 填充率是首帧大头），再放大到 target；**首帧不出接触阴影、不算雾视野、不算屋顶遮罩、不上传远郊 regions**；同一 rAF 链的下一帧立刻全分辨率 + 全要素重画（`forceRepaint` / `titleFrame=-Infinity`）。停留画面与 golden 逐像素一致（45/45 证明）。
2. **删除死 post 程序**：`POST_VERTEX/POST_FRAGMENT/postProgram/postBuffer/ensureSceneTarget` 从未参与绘制，删除后少一次 program 编译/链接。
3. **GL 装配延迟**：program/attrib/uniform/纹理装配从模块求值挪到首帧前（`ensureSetup`），失败不再炸整个模块（返回 false → 现有 gfx 失败路径）。
4. **网格构建热路径**：`quad()`、beam 端盖、`stageMesh` 三角形改成显式 15 参 `push`；`terrainWithNormals` 去掉了每顶点 3 次 `subarray` 与每三角形一次法线数组分配（算法与 `Math.hypot` 保持不变，输出逐位一致）。
5. **每帧上传复用**：`moving` / `translucent` 顶点改为复用一个 grow-only `Float32Array`，不再每帧 `new Float32Array(...)`（4 s 采样里 GC 41.8 ms）。

### B. 帧率（`web/app.js` + `shared/wild-landscape.mjs`）

1. **地形高度整数格缓存**：`wildLandscape.height(x,z)` 只对 4 个整数角点做双线性；新增惰性 `Float32Array`（NaN=未算）缓存 `rawHeight` 整数格。居民/动物贴地、接触阴影、视野射线重复问同一批角点时只付一次噪声成本；缓存是纯函数记忆，输出逐位不变（22k parity + golden 证明）。
2. **视野/屋顶射线节流**：`campVisibility` 位置量化从 0.25 放宽到 0.5 世界单位，并限制最多每 160 ms 重算一次（雾视野是表现层遮罩，不写世界状态）；`coveredModels` 按“玩家/镜头 0.5 格 + 各层 box 数量”缓存，未跨格直接复用。
3. **移动 DPR 保持 0.78**（原有），叠加上述 JS 减负后中位帧从 33.3 → 16.7 ms。

### C. buildWorld（`shared/camp-scene-content.mjs`）

- `roadDist` 内联 + 平方距离比较 + 桶 64→32 px（桶只影响候选段数量；任何 ≤40 px 的段都必落在查询点桶里，使用方阈值 ≤23 px/1.3 格，故 0–40 px 内取值逐位相同）。
- 效果：profile p50 281.1 → **237.1 ms**；官方 harness **225–232 ms**（目标 <300）。

### D. 加载（`serve.mjs`、`web/index.html`、`web/boot-prefetch.js`、`web/net.mjs`）

1. **gzip**：静态文本按内容 ETag 缓存压缩结果（≤128 条），JSON 响应 `>1KB` 即时压缩；`content-encoding: gzip` + `vary: accept-encoding` + 正确 `content-length`；woff2/png/ogg 跳过。`app.js` 265,891→98,896 B、`/world` 146,473→19,851 B、`app.css` 48,928→12,705 B、`index.html`→6,711 B（证据 `gzip-headers.txt`）。ETag/304 与 immutable 缓存头保持原语义。
2. **`/world` 预取**：`web/boot-prefetch.js`（head 里的小 classic script）在模块图下载前就 `fetch('/world?mode=…')`；`net.mjs` 的 `postJson` 优先消费一次，URL/内容不一致或失败自动回退。首帧前“模块结束 → buildWorld 开始”的空档从 ~54 ms 降到 ~23 ms（seg3 vs seg4）。
3. **modulepreload + 字体 preload**：`app.js`、`camp-3d-render.mjs`、`camp-scene.mjs`、`camp-scene-content.mjs`、`life/space.mjs`，以及 fusion-pixel woff2；请求数仍 51/47（≤60）。

## 5. 没做到/没做的事（profile 证据与替代方案）

1. **冷启动着色器编译 ~110 ms 仍在关键路径**。证据：`seg3/seg8` 里 `glSetup` 108.9–119.7 ms，而 `createCampRenderer` 只有 3.5–4.1 ms。试过的方案：延迟到首帧（只改位置，SwiftShader 惰性编译，没省总时间）、KHR_parallel_shader_compile（状态查询仍需等编译）、删除死 post program（已做，省一次 program）。
   剩余可选方案（未采用，均需权衡）：① Worker + OffscreenCanvas 预编译依赖 Chrome 磁盘 shader cache 命中，跨进程/驱动不保证，收益不可控；② 拆成多个更小 program 降低单次编译，但增加 draw call 与 link 次数，总时间未必下降且改渲染路径；③ 降低片元着色器复杂度会改变画面，golden 会红。**当前 688/509 ms 已满足闸门并留 91–120 ms 余量，不拿正确性换速度。**
2. **首帧 `stage` 网格 10.6 MB 构网格 + 上传 ~32 ms**。已把展开/法线分配优化到实测下限；再快要改成“生成时直接产出 MODEL_STRIDE 的 typed array”（会把成本挪进 buildWorld，同样在关键路径）或首帧只画 terrain 不画 props（会改变首帧内容）。**未做**。
3. **cold title（非闸门）波动 641–740 ms**。它包含与 cold survival 相同的 buildWorld + 冷 shader 编译，只是少了生存世界的位置/居民装配；本轮未把 cold title 设为目标，记录在此避免误读。
4. **机器负载会让单次数字漂移 ±15%**（§1）。最终结论用两轮同 harness 闸门 + 多轮 lean 探针（c4 5 次：cold 662–967、warm 489–513）交叉支撑；没有改 percentile/采样窗口。
