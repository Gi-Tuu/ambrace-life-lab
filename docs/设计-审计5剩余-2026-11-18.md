# 审计5 剩余大改设计（未实施项）

> 基线：`main@34c1aeb` + 审计5 Batch 0/1/2/3 已修（见 `docs/回报-审计5修复-2026-11-18.md`）。
> 本文只覆盖“改动面大、一次改完风险高”的两项：**ARCH5-06 预算/attempts 单源** 与
> **camp_* 前置检查收敛**。两项都不阻塞本批上线；下面给出可分批实施、可回滚的设计与验收。

## 1. ARCH5-06 剩余：预算记账单源（目前已完成一半）

### 现状

- 已统一：`modelBrain` / `modelTalk` 的车道与 token 记账改走 `budget.chargeLane()` / `budget.addTokens()`，
  不再手写 `nodeCalls/moneyCalls/tokens`；`observerActive` 已收敛到 `host-budget.mjs` 一份实现。
- 仍分叉：
  1. `S.model.calls += 1` 在 host 内部路径手写；`/chat` 走 `modelGate()`（先预扣）→ `modelCharged()`。
     两者对 `calls/reserved` 的语义不同：内部路径没有预扣，也不能在失败时回退。
  2. `attempts` 数组仍在 `host.mjs:387/441/453/479/496/502` 手写 push/shift；域对象没有对应入口。
  3. `survivalChoices` 仍是 host 手写（`S.model.survivalChoices`）。
- 风险：加车道/加指标要改两处；域单测覆盖不到内部路径，口径可能分叉。

### 设计（两步，可独立回滚）

**Step 1（低风险，建议先做）**：给 `createBudgetDomain` 增加：
- `attempt(note, cap)`：统一 attempts push + 截断；
- `choice()`：统一 `survivalChoices += 1`；
- `reserveCall()` / `settleCall(ok, tokens)`：把内部路径也改成“先预扣 calls、失败回退”，
  与 `/chat` 的 `gate/charged/release` 共用一套状态机。
Host 内部路径只调域方法，`S.model` 字段只由域写。

**Step 2（有行为风险）**：让 `/chat` 与内部决策共享同一个 `reserveCall` 入口；预扣失败时
`modelChannel` 的 `moneyCalls/nodeCalls` 判定改为“已结算数”，避免预扣与分账重复计数。
需同步检查 `host.test.mjs` 的每日预算用例、`serve-guard.test.mjs` 的 `/chat` 预留额度用例。

### 验收

- 新增对照测试：同一组 `(free, ok, tokens)` 下，内部路径与 `/chat` 路径对
  `calls/tokens/moneyCalls/nodeCalls/reserved/attempts` 的最终值逐字段相等；
- 失败/超时回退后 `reserved === 0`、`calls` 不泄漏；
- `npm test` 全绿，`/world.model` 载荷字段不变。

## 2. camp_* 前置检查收敛（validateCamp 只做“能不能”）

### 现状

`life/survplay.mjs` 的 `campAction`（约 700–930 行）仍保留大量前置拒绝：位置/距离、工具、背包、
场地/设施状态、动物状态等；`validateCamp` 只做 kind/成本/reach 三项。两者并存导致：
- 同一拒绝码可能在两处产生，顺序不同 ⇒ 错误码/文案随入口变化；
- 新增营地动作要在两处各写一遍，容易漏；
- `validateCamp` 的“唯一裁决点”声明不成立（审计 ARCH5-01/02 之后仍如此）。

### 设计（按动作族分批，不一次搬完）

1. **先加特征测试**：对每个 `camp_*` 动作，用固定世界夹具记录“成功/每个拒绝码”的当前输出
   （`campAction` 直接调用），作为搬迁前的金样；测试只锁行为，不锁实现。
2. **搬“静态前置”**（不依赖玩家连续位置）：工具、背包、场地/设施存在性、动物恐惧/距离。
   在 `rules.validateCamp` 增加可选 `ctx`（world/agent/body），返回同样的 code；`campAction`
   删除对应分支，只保留效果结算。
3. **搬“连续位置/服务端位置”**：`playerReach`、`distanceToRect`、`campPlayerRoom` 等依赖
   服务端位置的检查，放进 `validateCamp` 的 `reachFn` 扩展（传 from 时校验），避免暴露给伪造坐标。
4. **最后删重复注释/文档**：`campAction` 只做效果；`survplay` 顶部注明“规则层唯一裁决”。

### 风险与回滚

- 风险最高的是拒绝码顺序与 `settleSurvival` 的副作用（失败不扣时间/不回滚）。每搬一族都保留
  旧分支并用环境开关（如 `CAMP_VALIDATE_STRICT=0/1`）双跑一天，金样逐字段一致后再删旧分支。
- 回滚：按动作族 revert，`campAction` 旧分支在开关关闭时仍可用。
- 明确不做：`camp_sleep` 在 `survplay` 提前 return（不经过 validateCamp），属**有意例外**，
  在文档标注，不强行塞进规则层。

## 3. 本批未修的其他风险（已在回报正文列出）

- SEC5-05 令牌姿态下浏览器 MAIN `survival_reset` 仍不可用（令牌只认 Bearer，前端不发）。
- DATA5-01 首个 `SAVE_EVERY` 窗口仍可能无主档（flush/信号路径已强制补写，但硬杀进程仍可能丢 ≤10 刻）。
- DATA5-05 `ownerHash` 仍只存索引；索引丢失会丢归属（重建索引不恢复 owner）。
- `readIndex` 对坏 key 采用“读时过滤、下次写回”策略，不在读时改名，避免 merge 丢合法条目。
