## 4. iframe / CSP：本地只能证明“逻辑与浏览器执行”，线上未验证

**Header 事实**（已从真实响应解析，不是看源码）：

- `frame-ancestors 'self' https://*.ms.show https://modelscope.cn https://www.modelscope.cn` 精确存在；
- 所有响应（200/304/404/HEAD）**均无 `X-Frame-Options`**；
- 其余 CSP 指令保持 `default-src 'self'` 等原样。

**本地模拟方式**（Chrome headless + CDP）：

- 应用跑在 `http://127.0.0.1:7861`；另起一个**无 CSP 的普通父页** `http://127.0.0.1:7862`，避免把父页自己的 `default-src 'self'`（frame-src 回退）误当成 `frame-ancestors` 的证据；
- 用临时自签证书在 **443** 起 TLS 反向代理，`--host-resolver-rules` 把 `app.ms.show / platform.ms.show / modelscope.cn / www.modelscope.cn / evil.example` 指到本机；必须 **443**，因为 CSP host-source 不写端口时只匹配 scheme 默认端口；
- Chrome 需 `--no-proxy-server`（本机 PAC/系统代理会接管 DNS，实测会让 `app.ms.show` 走公网并重定向）与关闭 Private/Local Network Access 检查（域名指向 127.0.0.1 后会被本地模拟这层额外拦掉）；跨源 iframe 是 OOPIF，需单独 attach 到 iframe target 读 `cvA`。

| 用例 | 期望 | 实测 | 证据 |
|---|---|---|---|
| `app` 同源嵌入 `app`（'self'） | 放行 | ✅ 加载 + cvA | iframe.json |
| `http://127.0.0.1:7862` 父页嵌 `:7861` | 拦 | ✅ `frame-ancestors` 违规日志 + Audit issue，顶层直开可渲染 | 同上 |
| `https://platform.ms.show` 嵌 `app.ms.show` | 放行（`*.ms.show`） | ✅ 加载 + cvA | 同上 |
| `https://app.ms.show` 嵌 `app.ms.show` | 放行（'self' + 通配） | ✅ | 同上 |
| `https://modelscope.cn` 嵌 `app.ms.show` | 放行（精确域名） | ✅ | 同上 |
| `https://www.modelscope.cn` 嵌 `app.ms.show` | 放行（精确域名） | ✅ | 同上 |
| `https://evil.example` 嵌 `app.ms.show` | 拦 | ✅ 违规日志 + Audit issue | 同上 |
| `http://127.0.0.1:7862` 父页嵌 `https://app.ms.show` | 拦 | ✅ 违规日志 + Audit issue | 同上 |
| 对照：每个被嵌 URL 顶层直开 | 可渲染 | ✅ | 同上 |

- **模型端点/密钥**：只从环境变量读；镜像/前端/仓库都不含密钥（§2 已审计）。平台侧把 `MODEL_KEYS`、`MODEL_PROVIDERS`、`CTL_TOKEN` 等放**密文变量**，其余明文。不要在 Dockerfile、`.env` 或构建参数里写密钥。

### 6.3 CSP / 缓存 / 健康检查 / 回滚

- **CSP**（服务端统一头，已实测）：`default-src 'self'; …; frame-ancestors 'self' https://*.ms.show https://modelscope.cn https://www.modelscope.cn`；**不设 `X-Frame-Options`**（设了会把平台 iframe 拦成白屏，2026-11-19 线上事故根因）。注意 `frame-ancestors` 的 host-source 未写端口 ⇒ 只匹配 443；平台若走非 443 需重新评估。
- **缓存**：静态文本/JS/CSS/HTML 带内容 ETag + `cache-control: no-cache, must-revalidate`（刷新走 304）；带 `?v=<指纹>` 的请求 `public, max-age=31536000, immutable`；文本/JSON/SVG ≥1 KB 自动 gzip（`vary: accept-encoding`），woff2/png/ogg 不二次压缩；`/world` JSON 同样 gzip。
- **健康检查**：Docker 内置 `HEALTHCHECK` 每 30 s 请求 `http://127.0.0.1:7860/healthz`（timeout 10 s、retries 3）；平台探活建议 GET/HEAD `/healthz`。`saveError`/`tickError` 时返回 **503**，正常 200；HEAD 也支持。`/healthz` 不回显密钥/端点/数据目录。
- **回滚**：
  1. 保留上一个可用镜像的 digest/版本（平台版本历史）；回滚 = 重新部署旧版本，**继续挂同一个 `/data`**。

  3. 回滚后验：`/healthz` 200、`/world` 里 `survival.t` 在走、名字营地 `/saves` 可见。
  4. 主世界存档带 `schemaVersion`（当前 1；缺失视为旧档=1；更高版本按兼容模式载入并给 `schemaWarning`，不拒载）。**回滚到旧镜像前，仍建议先用一份生产数据副本在本地起旧镜像验证**；不行就保留备份并从种子重开（会丢实时历史）。
