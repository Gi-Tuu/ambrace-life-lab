## 2. 逐条对上

### 2.1 talk_say / camp_sleep / compare 迁出旧 tickChain

- `host.act` 在正式世界（`simClock` 存在）把所有 survival 动作交给 `actSurvivalFast`，只排 `queueAct`；研究态没有 `simClock`，仍走旧 `queueWorldWrite`（T25 等研究态时序不变）。
- `talk_say` 两阶段：
  1. `queueAct(() => prepareSay(...))`：校验在场/耐心/词表，写入玩家这句；
  2. **锁外** `await modelTalk(...)`；
  3. `queueAct(() => finishSay(...))`：重验在场/耐心/`pendingSay` token 后落地。
  - 模型等待期间普通输入不被锁住（`P1c-02` 实测 `busy_cancel` < 500ms）；
  - 并发第二句返回 `SAY_PENDING`，只调一次模型；`pendingSay` token 防止两段 finish 互相覆盖；
  - 模型迟到超过耐心 ⇒ `left`，不把迟到台词说出口。
- `camp_sleep` 在短锁内按 `tickSurvPlay({minutes:60})` 推进同一连续时钟；P1c-03 实测 tick 在途时 sleep 仍返回（<2.5s），睡眠期间其它输入排在同一短锁后（写清并有测试）。
- compare（`GAME_MODE=game`）动作走 `queueAct`，P1c-09 实测 tick 在途时 compare 输入 <1s 返回。

### 2.2 正式路径 0 `TIME_WAIT` / 0 每拍配额

- 正式文件里已无 `TIME_WAIT` 字面量（`evidence/debt-time/formal-timewait-scan.txt`：0 命中）；唯一定义在 `life/research-time.mjs`。
- `ARCH-2D-01` 白名单从 3 处收紧为 1 处（research-only），换文件/换行/注释都红。
- 删掉 `world.think.maxPerTick` 死配额；`CHAIN_MAX` / `TICK_ACTION_CAP` / `residentActionsAt` / `p1Budget*` 全部只落在 `!simClock` 研究分支。
- `host-model` 的 `MAX_CALLS_PER_TICK` / `UNATTENDED_CALLS_PER_TICK` 对连续时钟正式世界不生效；P1c-08 在 `MAX_CALLS_PER_TICK=1` 下同刻两个事件仍产生 2 次真实模型调用。

### 2.3 `world.t` 降级为派生整数

- 正式世界：`Object.getOwnPropertyDescriptor(w,'t').get` 存在且可枚举；`w.t === floor(simClock.nowMinutes()/60)`。
- 写 `w.t` 只用于存档/旧档迁移/测试重锚（setter 转 `setGameMinutes(value*60)`）；正式模块（`survplay/agent/resident-time/survplay-actions/host*` 等）写 `w.t` 由 `ARCH-CLOCK-01` 直接判红。
- `dumpSurv` / `JSON.stringify` / `structuredClone` / `loadSurv` 全部实测（P1c-05）：`t=12`、`clock.gameMinutes=720` 往返一致。
- 时间轴关键路径改为 `worldTick()`/`clock.nowMinutes()`：`tickSim` 的分钟边界、`worldTick`、`sleepSurvival`、host 补时/状态不再依赖 `w.t` 作为事实。

### 2.4 感知快照：think 同步、事件只消费一次

- 正式世界 `world.percepts` 不再在跨 60 分时整清；每条事件带 `seq`（`emitPercept` 同时写 `at`）。
- 每个居民维护 `lastPerceptSeq`：只消费新 seq 的事件；`decidedAt` 记下本轮 think 的决策分钟（`a.lastPerceptDecidedAt` / `a.lastPercepts`）。
- 异步/排队 think 迟到时，`now - at > 60` 的事件丢弃，写 `layer:'percept_expired'` trace，并计 `perceptExpired`；不会补消费。
- busy 居民仍在分钟调度里获得 think（P1-03），因此仍能感知。
- 研究态没有 simClock：仍按旧“每刻 `w.percepts=[]`”路径，`dumpSurv` 逐位不变。

### 2.5 离线补时 / 暂停 / 倍速同一 rate/step

- 唯一换算仍是 `gameMinutesForRealMinutes(minutes, clock)`（`SimScheduler` 与 `catchUpSurvival` 共用）。
- `/ctl rate` 直接改所有生存世界 `clock.setRate(rate)`；在线调度读 `clock.rate`，离线补时读同一个 `clock`。P1c-06：rate=2 时 60 真实分补 120 游戏分（不是 240/60）。
- 暂停走 `clock.pause()/resume()`（恢复时 anchor 后移，暂停不欠不补），补时在暂停状态下只推进暂停点。
- 正式启动/手动补时不再对 A/B 跑第二套 `catchUp`；A/B 只在研究态保留旧补时。

### 2.6 居民生理：每 60 分一次，不是 6 倍

- 同一派生刻内多个 10 分 think 复用 `lastMetab`，只结算 1 次基础代谢；跨刻（或错过的刻）按 `elapsedTicks` 补时间。
- P1c-07：50 游戏分 5 个 think ⇒ `metabCount` +1、`viab.age` +1；跨到下一刻 ⇒ +2，不是 6。
- 研究态保持旧的“每次 tick 一单位”，反射刻不补代谢，逐位基线不变（settlement-events 风暴轨迹实测恢复原值 0.42）。

**剩余（如实）**：M5 快/慢仓 `tick(dt)` 只接受 `dt=1`，完整 Body 分钟级 micro-step 没有做；正式世界仍按派生刻结算（M5 缺口记 `metabRemainder`，只观测不入档）。影响是“刻内饥饿/代谢时点”粒度 60 游戏分，不是 6 倍速率。

## 3. 研究态如何隔离

- 唯一旧时间行为模块：`life/research-time.mjs`（`RESEARCH_ONLY`）。
- 调用点只有三个共享模块的 `!world.simClock` 分支：`resident-time.mjs`、`survplay-actions.mjs`、`agent.mjs` 的文案映射。
- `host.mjs` / `host-world.mjs` / `survplay.mjs` 编排层不 import 该模块；正式世界走连续时钟 + 短锁。
- 研究态仍走 `queueWorldWrite` + 旧每刻/每日池；`research-time.mjs` 的 `TIME_WAIT` 是 `ARCH-2D-01` 唯一白名单。
- 研究 `dumpSurv` 逐位不变：`p1-continuous-clock` P1-05 + 五份研究 md5（见 §4）。

## 5. 已知边界（本轮不做，不留“下一轮时间债”）

1. **M5 micro-step**：`M5ModulatorBank.tick` 只接受 `dt=1`，完整分钟级 Body micro-step 不可用；正式世界按派生刻（60 游戏分）结算，`metabRemainder` 记录 M5 未细分的刻。非 M5 世界已按 `elapsedTicks` 补时间。
2. **sleep 的阻塞语义**：一次睡眠是短锁内的原子事务（同步推进、无模型等待），睡眠期间的其它**状态写输入**排在其后；读路径始终不阻塞。这是有意选择，已由 P1c-03 钉住。
3. **compare 的时间模型**：compare 分支仍强制旧每刻结算（研究/回放可复现），但动作入口已迁到短锁；compare 的“连续时钟化”不在本轮范围，避免破坏研究态 dump。
4. **具名营地**：共享主世界同一套 rate/step，但没有独立定时器（仍由主 tick 带动）。
5. **前端**：只读 `survival.gameMinutes/clock`，没有做世界分钟插值/倍速 UI 动效。
6. **移动/抵达**：`districtTravel.arrive` 仍是整数刻粒度（P1b 已知边界）。
